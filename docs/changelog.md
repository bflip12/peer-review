# Changelog

Dated record of rule and style changes, newest first. Each entry says what changed and why.

## 2026-11-03

- `steward` skill: the safety-net check-in while CI runs waits twice the average CI run
  (about 10 minutes), not an hour. Claude posts the Vercel preview link when the latest
  commit's deployment is ready, and each "ready" message has a "What to test" list.
  `.claude/rules/voice.md`: replies give times in Alberta time, never UTC. Reason: Bobby
  tests each PR on its preview, and a 50-minute check-in left a green PR waiting.

- `.claude/settings.json` allows `git checkout -b`, `git checkout -B`, and `git switch`
  without asking. Reason: starting the next task's branch from `main` asked Bobby each
  time.

- New `steward` skill: Claude subscribes to each task's PR, fixes red CI, marks the PR
  ready when CI is green, and checks Migrate after the merge. It sends a push notification
  when a PR is ready, after Migrate, and when it needs Bobby's decision. `CLAUDE.md` rule 7
  now says Bobby merges. Reason: Bobby is not watching the chat while CI runs, and keeps
  the merge as his own step.

- `CLAUDE.md` lists `npm run db:cities`, which writes the cities seed migration from
  GeoNames (ADR 0025), and the `NODE_USE_ENV_PROXY=1` prefix it needs in cloud sessions.
  Reason: the seed is regenerated by script, never edited by hand.

## 2026-10-30

- `npm run screenshot` takes `--as=user` or `--as=new` to capture pages signed in. It
  creates a user on the local stack, signs in through `/auth/confirm`, and deletes the user
  afterwards. Captures now wait for the network to go quiet, so streamed content has
  replaced its loading fallback. Reason: rule 3's screenshots must cover pages behind
  sign-in.

- `.claude/rules/voice.md`: replies name the service and the project or environment in
  every instruction ("Supabase, staging project: ..."). Reason: setting up sign-in, steps
  for Supabase, Vercel, and GitHub were mixed up when a reply said only "the project".

## 2026-10-29

- End-to-end tests run in CI's database job, after `npm run db:env`, since sign-in needs
  the local stack (ADR 0022). `npm run db:start` now starts Mailpit, which catches the
  stack's sign-in emails. New `npm run db:env` command. Reason: the tests follow real
  sign-in emails.
- `migrate.yml` applies migrations to the staging project too, in its own job, with the
  `SUPABASE_STAGING_DB_URL` secret. Reason: preview deploys use staging (ADR 0018).

- New `.claude/rules/security.md` for `src/**`: identity from `getClaims()` or
  `getUser()`, never `getSession()` on the server; only `NEXT_PUBLIC_*` reaches the
  browser; no service role key under `src/`; untrusted input in redirects and HTML.
  Reason: Milestone 1 adds auth, and these are the mistakes Next.js's and Supabase's docs
  warn about.
- New `.claude/rules/workflows.md` for `.github/**`, writing down what the workflows
  already do: SHA-pinned actions, read-only permissions, no persisted credentials,
  timeouts.
- `.claude/rules/database.md` gains SQL and policy style: Supabase's naming conventions,
  Postgres's constraint name pattern, one policy per operation, `(select auth.uid())`.
- `docs/code-style.md`: `T | null` for database values and `?:` for optional inputs (was:
  `Maybe<T>`, which the project never defined); Testing Library's query priority (was:
  forward `data-testid` on every component tests drive); an end-to-end section; React 19
  and Next.js 16 points (`ref` as a prop, `<Context>` as provider, keys, `&&`,
  `PageProps`); effects only for syncing with outside systems; a new section 13 on
  accessibility, so the checklist is section 14. "Mixed-type collection" is dropped from
  the cases every test covers, since TypeScript rules it out.
- Lint fails on warnings, in CI and in the edit hook (ADR 0021). Reason: warnings exited 0,
  so `exhaustive-deps` and every accessibility rule were never reported.
- ESLint enforces the mechanical rules of `docs/code-style.md` (naming, `type`, return
  types, arrow functions, named exports, no `React.FC` or `forwardRef`, `curly`,
  floating promises, the full `jsx-a11y` set). Stylelint checks CSS, with colors only from
  tokens. Reason: a lint error reaches Claude after every edit; a rule in a document only
  when remembered.
- The React Compiler is on. Code-style section 6 drops the rule that handlers a hook
  returns use `useCallback` (was: every returned handler memoized by hand).

## 2026-10-27

- `docs/code-style.md` sections 8 to 10 are rewritten for this stack (ADR 0019): CSS
  Modules with token variables, server components reading through `data/` functions,
  server actions validated with Zod, where state lives, and errors and loading with
  `error.tsx`, `<Suspense>`, and `notFound()`. Section 2's folder example, section 7's
  reducer, section 12, and the checklist follow (was: styled-components, React Query,
  Sentry, atoms, Immer). The route-file `export default` exception moved into code-style.
  Data function tests are `*.db.test.ts` beside the code and run with `npm run test:db`.
  Reason: the old sections described a different stack.
- The Migrate workflow connects to the hosted database with one secret,
  `SUPABASE_DB_URL` (the session pooler URL), and no Supabase access token (was: an
  access token and `supabase link`). Reason: `supabase link` needs a token that can read
  the project's API keys, including the service role key, which bypasses RLS. Both steps
  only need a Postgres connection.
- CI installs only the Chromium browser for Playwright, not its system packages (was:
  `--with-deps`). Reason: that step spent 7 of the job's 8.5 minutes on a slow Ubuntu
  mirror fetching fonts the tests do not need. E2e stays on every PR; it takes 2 seconds.
- `.claude/rules/supabase.md`: every migration works with the live app (add before use,
  remove after use, rename in steps). `CLAUDE.md` describes deploys: never apply a
  migration by hand. Reason: Vercel and the migration job run at the same time on a merge
  to `main` (ADR 0018).

## 2026-10-23

- CI on GitHub Actions (`.github/workflows/ci.yml`) checks every PR and every push to
  `main`, and `CLAUDE.md` describes it. Actions are pinned to commit SHAs (was: no CI).
  Reason: a clean machine catches what only works in one container, and a SHA cannot be
  moved to different code the way a tag can.

## 2026-10-22

- Rule 3 names `npm run screenshot` and says the captures are read before a UI task is
  called done (was: screenshots at 375px and 1280px, with no tool). Reason: the script
  now exists, and a capture nobody opens checks nothing.
- Rule 7: GitHub deletes the branch on merge (was: delete the branch after the merge).
  Reason: the repo deletes merged branches automatically.
- `CLAUDE.md`: the cloud Chromium prefix applies to `npm test` and `npm run screenshot`
  as well as `npm run e2e`, and the allowlist covers it for every npm script. Reason: the
  screenshot script's test launches a browser.
- `docs/ai-log.md` is grouped by stage, from idea to code, with entries oldest first in
  each stage (was: one list, newest first). How AI is used is described once per stage,
  and an entry adds one sentence only when it differs. The `ai-log` skill writes entries
  this way. Reason: Bobby wants the log to read as the overall process, and the same
  detail in every entry was getting too specific.
- `.claude/settings.json`: a `PostToolUse` hook on `Edit|Write` runs Prettier and
  `eslint --fix` on the edited file, and exits 2 with any errors left so Claude fixes them
  in the same turn. Markdown is skipped. Reason: formatting no longer depends on anyone
  running `npm run format`, and lint errors show up at the edit, not at the end of a task.
- `.claude/settings.json`: an allowlist for the npm scripts, `npx` runs of the project's
  tools, and git, including `add`, `commit`, and `push`. Deny rules block force pushes and
  pushes to `main`. Reason: rule 7 pushes after every commit, and asking each time added
  up. The deny rules match command text, so they cover the usual commands, not every way
  of writing one.
- `package.json` sets `"type": "module"` and Node 22.18 or later. Reason: Node runs the
  TypeScript hook directly, and 22.18 is the first Node 22 release that does so without a
  flag.

## 2026-10-13

- `.claude/rules/database.md`: a one-value enum column is allowed only when the enum table
  in `docs/DATA_MODEL.md` names the value expected next and the feature that brings it
  (was: any state that could gain a value). Reason: the old wording contradicted the rule
  against adding a column in case a feature arrives. Enums still replace booleans.
- `.claude/rules/database.md`: each table lists who writes which column, enforced with
  column grants or a trigger, with a test per protected column. Function security rules
  live in `.claude/rules/supabase.md`. Reason: RLS picks rows, not columns, so an owner
  update policy alone lets a user set their own role to admin through the API.

## 2026-10-09

- Rule 7: a branch is deleted after its PR merges, and the next task starts a new branch
  from `main`. Reason: a squash merge leaves the branch's commits outside `main`, so reusing
  the branch needs a force push.
- Rule 7: commits happen as work progresses, and PRs are squash-merged so `main` still gets
  one commit per task (was: one commit per finished task). Rule 10 and the `ai-log` skill
  now run before a task's PR is marked ready. Reason: a draft PR from the start of a task
  only backs up work if work in progress is committed.
- ADRs can be edited freely until their PR merges (`docs/adr/README.md`). Reason: Bobby
  confirmed that a pending ADR is still a draft. The no-rewrite rule protects decisions
  already merged.
- Rule 7: a draft PR opens with a task's first commit and is marked ready when the task is
  done (was: a PR at the end). Reason: Bobby wants work backed up and visible online from
  the start of a task.
- Rule 7: work happens on a branch, never on `main`, and the branch is pushed after each
  commit. It merges to `main` by PR when the work is finished (was: push only when asked).
  Reason: the work is saved on GitHub throughout, and cloud containers are deleted after
  inactivity. The review gate is the merge.
- Rule 7: Bobby stays the commit author. In cloud sessions the committer is Claude
  <noreply@anthropic.com>, so GitHub shows the commit as verified. Reason: committing with
  Bobby as committer made the session amend every commit afterwards.

Planning session. Product decisions are in `docs/adr/` and `SPEC.md`; the entries below are
changes to how sessions work.

  lower adherence. Detail moved to the files below.

  requirement, and screenshots catch layout problems tests miss.

  Decision Record in `docs/adr/`. Reason: Bobby wants a record of how and why the app took
  its shape, readable years later.
- `docs/code-style.md` is now this project's own copy. Changes no longer go to the portfolio
  copy first. Reason: this project will change it, and those changes may not apply to the
  portfolio.
